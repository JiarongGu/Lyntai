# Lyntai 1.0 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Cut Lyntai **1.0.0** — verify the public surface survived adoption (thorough adversarial API review + read-only consumer review), land any final breaks before the permanent freeze, collapse the accreted 0.x migrations into per-domain baselines (data-loss-OK reset), update docs, and reach a verified-green "ready to tag" state.

**Architecture:** Four sequential phases with gates. Phase 1 (review) must complete before Phase 2 (squash) so the frozen schema is final. The squash is **snapshot-driven**: dump the authoritative post-migration schema, derive per-`StorageFeature` baselines from it, and gate correctness on a schema-equivalence test — never hand-recompute the net schema (the CuratedMemory domain adds-then-drops columns, so a naive concatenation would be wrong). SQLite copies stored DDL verbatim (byte-identical `sqlite_master`); Postgres re-expresses the net schema and compares normalized catalog state.

**Tech Stack:** .NET 10, FluentMigrator (numbered `YYYYMMDDNNNN`, tag-gated per D15), Dapper, xUnit, SQLite (`Microsoft.Data.Sqlite`) + Postgres (Npgsql + Testcontainers), `node devtools/dev.mjs` dev loop.

- **TDD:** failing test → run-fail → minimal impl → run-pass → commit. Storage integration tests run against a per-test temp DB.

- **The gate:** `node devtools/dev.mjs verify` (build → test → e2e → leak scan) is the "am I done" check.

- **Branch:** decide at handoff whether to work on `master` (repo convention) or a `1.0-prep` branch (cleaner for the many commits). Not a code task — a checkpoint.
- **API-surface changes update `ApiSurfaceTests` baselines deliberately** (a public-surface change is intentional, reviewed).

## Phase 2 — Migration baseline squash (WS2)

**Goal:** collapse 16 SQLite / 14 Postgres migrations into **9 per-`StorageFeature` domain baselines** each, folding each domain's ALTERs into its `CREATE`, preserving D15 tag-driven selective migration. Data-loss-OK reset: consumers drop their `lyntai_*` tables on upgrade.

**Domain → objects (the partition):**

|---|---|---|
| KeyValue | `lyntai_kv` (+ its indexes) | 170001 |
| Conversation | `lyntai_thread`, `lyntai_message` (+ indexes) | 170002 |
| Memory | `lyntai_memory_entry`, `lyntai_memory_fts` (+ shadow tables, 3 triggers, `ux_lyntai_memory_dedup`, `ix_lyntai_memory_expiry`) | 170003 + 170007 (`expires_at`+index) + 220002 (`last_accessed_at`, content-only AU trigger) |

| Jobs | `lyntai_job` (+ indexes) | 180001 |
| Governance | `lyntai_response_cache` (+2 indexes), `lyntai_usage`, `lyntai_vector` | 180002 |
| CuratedMemory | `lyntai_curated_memory` (final cols: `id,kind,content,enabled,created_at,updated_at,task,scope,metadata` — **no `source`/`title`**), `lyntai_curated_meta` (+`ix_lyntai_curated_meta_kv`), `lyntai_curated_fts` (**content-only**, +shadow, +3 content-only triggers), `ix_lyntai_curated_memory_kind`, `ix_lyntai_curated_memory_task` | 180003 + 220001 (`task`,`scope`,index) + 270001 (`title`) + 270002 (title-aware FTS) + 270003 (metadata; **drops `title`,`source`**; rebuilds FTS content-only) |

The CuratedMemory NET state is why we snapshot instead of concatenate: `source` (from 180003) and `title` (from 270001) are both **gone** by 270003, and the FTS is content-only, not the title-aware one 270002 created.

**New migration numbers:** one fresh date, sequential, never reusing an old number: `202607280001`…`202607280009` in domain order (KeyValue=0001 … CuratedMemory=0009). Valid because `202607280001 > 202607270003` (the current max).

- [ ] **Step 1: Write the equivalence test.** It migrates a fresh temp DB and asserts the `lyntai_*` schema equals the committed golden. `LYNTAI_UPDATE_SCHEMA_SNAPSHOT=1` regenerates the golden (used now to capture, and later only for deliberate schema changes).

```csharp
using System.Runtime.CompilerServices;
using System.Text;
using Dapper;

namespace Lyntai.Tests.Storage;

/// <summary>The load-bearing gate for the 1.0 baseline squash: a fresh migrate must produce a net
/// lyntai_ schema byte-identical to the golden captured from the pre-squash migration set. Regenerate
/// ONLY on a deliberate schema change: LYNTAI_UPDATE_SCHEMA_SNAPSHOT=1.</summary>
public class MigrationSchemaSnapshotTests : IDisposable
{
    private readonly TempDb _db = new();
    public void Dispose() => _db.Dispose();

    [Fact]
    public void Fresh_migrated_schema_matches_golden()
    {
        var actual = DumpSchema();
        var goldenPath = Path.Combine(SnapshotDir(), "sqlite-schema.sql");

        if (Environment.GetEnvironmentVariable("LYNTAI_UPDATE_SCHEMA_SNAPSHOT") == "1")
        {
            Directory.CreateDirectory(SnapshotDir());
            File.WriteAllText(goldenPath, actual);
        }

        Assert.True(File.Exists(goldenPath), $"golden missing: {goldenPath}");
        Assert.Equal(Norm(File.ReadAllText(goldenPath)), Norm(actual));
    }

    private string DumpSchema()
    {
        using var conn = _db.Factory.Open();
        var rows = conn.Query("""
            SELECT type, name, sql FROM sqlite_master
            WHERE (name LIKE 'lyntai\_%' OR name LIKE 'ix_lyntai\_%' OR name LIKE 'ux_lyntai\_%') ESCAPE '\'
              AND name <> 'lyntai_version_info' AND sql IS NOT NULL
            ORDER BY type, name
            """);
        var sb = new StringBuilder();
        foreach (var r in rows) sb.Append($"-- {r.type} {r.name}\n{r.sql};\n\n");
        return sb.ToString();
    }

    private static string Norm(string s) => s.Replace("\r\n", "\n").TrimEnd();
    private static string SnapshotDir([CallerFilePath] string f = "") =>
        Path.Combine(Path.GetDirectoryName(f)!, "Snapshots");
}
```
