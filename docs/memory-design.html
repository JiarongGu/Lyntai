Memory that forgets, and relinks

Recall today is one shot: take the top k, flatten it into four thousand characters, send. This is a design for the other shape — open with a cheap index, and pay for depth only along the direction you turn out to need.

Where it stands

Three memory systems, and no way to have two of anything

Lyntai already has lexical memory, semantic memory and a curated catalog. Every one is registered as a single unnamed singleton, so an application wanting a chat memory and a project memory has to wrap all of it itself — the same wrapper in every consuming application, none of them able to share it, because it lives above the library.

Three things follow from the flat shape, and all three worsen the longer an application runs.

  • Nothing fades. A hard TTL set at write time is the whole lifecycle. A fact recalled fifty times ranks identically to one written once and never used again.
  • Nothing connects. Entries are independent rows, so there is no thread to follow from one to the next.
  • The first load is the whole load. Context has to be in the prompt to be available, so a large memory is paid for on every turn whether or not any of it proves relevant.

And the composer fills a flat character budget in rank order — so a burst of loosely-relevant recall can push a hard constraint out of the prompt entirely, with nothing reporting it. The prompt still looks full. That is an accuracy regression hiding inside a convenience feature.

The shape

Index first, depth on demand

An entry becomes a node carrying a short headline and full content. Recall returns headlines; expansion returns content plus neighbours. Nodes connect by weighted edges, and each carries a retrievability that decays with time and is reinforced by use. 

RecallAsync(...)                       ~200 chars opens the session
  "user prefers terse commit messages"     #12  →4  r=.91
  "build gate is dev.mjs verify"           #47  →9  r=.88
  "GBK console mangles UTF-8 writes"       #31  →2  r=.55

ExpandAsync(#47)                       depth costs one hop
  full content of #47 + its 9 neighbours' headlines

Two consumers ride the same engine. A composer walks it automatically under a budget with no extra turns, and works with every provider including those with no tool support. A tool set lets the model walk it itself — that is the half that literally delivers the further it digs in one direction, the more it gets.

Spec A · lands first

The memory engine seam

One interface, resolved by name the way IHttpClientFactory resolves clients — the pattern .NET developers already know. Registration is a DI collection keyed by Name, mirroring ILlmProvider keyed by Id and picked by ILlmRouter. A fourth kind of memory is a class plus a registration; nothing existing is edited. 

public interface IMemoryEngine
{
    string Name { get; }
    Task<MemoryRef>    RememberAsync(MemoryWrite write, CancellationToken ct = default);
    Task<MemoryRecall> RecallAsync(MemoryQuery query, CancellationToken ct = default);
    MemoryGrades       Supported { get; }   // which grades it can store
}

// optional capabilities — an engine must not pretend
IExpandableMemory · ILinkableMemory · IForgettableMemory

A blend of sources is an engine, so naming, blending, remembering and expanding are one concept rather than four. Members are themselves named engines, hierarchically — which is what makes expansion route unambiguously. 

services.AddLyntai(cfg => cfg
    .UseSqliteStorage(...)
    .AddMemory());                       // zero config: one working engine, nothing to implement

// …or, for an application that wants to differ
    .AddMemoryEngine("chat", e => e
        .UseLexical().UseSemantic().Budget(1500))

    .AddMemoryEngine("project", e => e
        .UseCurated(kind: "glossary").Reserve(1200)     // → "project/glossary"
        .UseGraph(g => { g.Hops = 2; g.Reinforce = 0.5; })   // → "project/graph"
        .Budget(3000))

    .AddMemoryTools("project")                 // project_recall / project_expand
    .UseMemoryComposer("chat");
A seam is an escape hatch, never the answer to “how does this work”. Every seam ships with a registered default, and one line produces a working memory system. The fluent builder exists for applications that want to differ — never for applications that want it to work.

There is deliberately no separate composer type: composing a prompt is something an engine does, so “several composers” is already “several engines”. The whole knob budget is eight, all defaulted, all documented. Every public type is a permanent promise under semantic versioning, so the count is the point.

The constraint that shaped everything

Human-shaped recall, machine-grade precision

Human memory is good at association and bad at precision. If associative recall competes on equal terms with facts that must be exact, the result is worse than the flat dump it replaced — and it fails plausibly, which is the worst failure available. So material carries a grade, defaulted per member and overridable per entry.

AssociativeAuthoritative
Retrievabilitydecaysfixed 1.0, never decays
Reinforcementstability grows on recallno-op — nothing to reinforce
Headlinederived when not authorednever derived; full content returned
Budgetspends what is leftreserved pool first, then precedence
Edgesnormalnormal — grade affects ranking, not connectivity
Prune by retrievabilityeligiblenever eligible, with no special case

“Never derived” is not a preference. A headline reading the build gate is dev.mjs when the content says dev.mjs verify is worse than having no memory at all, because it is confidently wrong.

Three guarantees follow, and each is pinned by a test:

  • Routed, never downgraded. An authoritative write goes to a member that can hold one, or it throws. Accepting it and quietly storing it as associative is the exact failure this section exists to prevent.
  • Reserved, not first-come. Authoritative material is allocated before associative content is admitted. Flood the associative side with high-relevance noise and the hard fact is still there.
  • Never silently dropped. If it still cannot fit, the prompt carries … 3 further authoritative facts omitted (budget). A prompt that looks full while missing a constraint is not acceptable.

The two grades render as separate labelled sections, so the model is told which material is exact rather than left to guess. The authoritative section is byte-deterministic across repeated recalls — no decay, no ranking — which is what makes it trustworthy for concrete logic.

Spec B · lands second

The graph engine

Contracts in Core; implementations in the three storage adapters that already exist. Two tables, one migration, no new package.

Forgetting is measured in what has happened, not in elapsed time

The first cut borrowed the model wholesale from human memory research, where decay is measured in real time because that is what a person experiences between encounters. An agent does not work that way — and the failure is not subtle: 

one session, 8 hours, 500 writes   -- wall clock: almost nothing decayed
two sessions a month apart, 3 each -- wall clock: everything decayed

// the second experienced almost nothing and forgot everything.

So the clock is interference — a trace fades because newer material competes with it. Each engine keeps a position that advances when something is written to it, and an entry's age is a subtraction against it. A rarely-used memory therefore decays slowly and a busy one decays fast, automatically; the position is per engine, so a quiet project memory is not aged by a busy chat memory beside it. Reading never ages anything.

What that position counts is genuinely ambiguous — the number of things written, how much material, how much real time — so it is supplied rather than assumed, exactly as the curve is: 

public interface IMemoryClock { MemoryTick Advance(MemoryWrite write); }

PerWriteClock       → by count               // the default
ContentSizeClock    → by volume              // a document crowds harder than a note
BurstDampenedClock  → wraps any of them      // see below
ElapsedClock        → by real time           // calendar decay, opt-in per engine

public interface IRetrievabilityPolicy
{
    double Retrievability(in MemoryDecayState state);   // no clock: age is dimensionless
    double Reinforce(in MemoryDecayState state);
    double InitialStability { get; }
    double CandidateCutoff(double minRetrievability);  // conservative superset
}
Bursts must saturate, or a bulk ingest erases everything. Advancing once per write is linear, so ingesting a 500-item document ages every pre-existing entry by 500 — at any sane half-life, all of it gone. Reading a long document must not wipe your memory of the project. Damped, a burst advances by about ln n — 200 rapid writes cost about 6, not 200 — and its own items start at a shorter half-life. Together, that is why a person can read a book without forgetting their own name and still not recall most of the book.
The stability ceiling closes a real defect, not a rough edge. Unbounded stability × 1.5 compounds: about twenty recalls turn a twenty-event half-life into a hundred-thousand-event one. A hot associative entry would become permanently retrievable while still labelled associative — silently acquiring authoritative durability without any of its guarantees. MaxStability caps it, so “very durable” never quietly becomes “never forgotten”.

Where edges come from

The floor is model-free, because the feature has to work with no embedder registered — and because the mechanism most like a brain happens to be the one that costs nothing.

SourceTriggerModel
Co-activationnodes returned together get an edge; recurrence strengthens itno
Structuralshared scope, or a shared metadata keyno
ExplicitLinkAsync(from, to, kind, weight)no
Similarityon write, link to the k nearest existing nodesyes — enrichment only

Co-activation writes symmetric pairs so traversal is a single indexed lookup, and is capped at the top five returned nodes — a k=10 recall would otherwise write 45 edges every turn.

Recall, in five steps

1

Seed

FTS match on the query, plus semantic seeds when an embedder exists. Authoritative in-scope nodes are admitted unconditionally, query or no query.

2

Spread

For each hop, pull the frontier's neighbours ordered by weight × r, capped per hop.

3

Score

relevance × r × 0.5^hop. An entry is hidden only if it falls far below the strongest hit — buried by something else, never cut for its own faintness.

4

Budget

Authoritative reserve first, then associative by rank until the character budget is spent.

5

Touch

One batched update reinforcing the nodes actually returned, plus the capped co-activation edges.

Recall now writes. That is a real change in character, so it is designed rather than discovered: the touch is best-effort and a failure still returns the hits — a read-only database degrades to “no learning”, never to “no memory”. Concurrent touches are last-write-wins and benign, since two sessions reinforcing the same node both mean to.

Expansion returns a node's full content plus its neighbours' headlines — and touches the expanded node. Digging in one direction is therefore exactly what makes that direction more retrievable next time, which is the property the whole design is named for.

Two traps, named before they ship

The failures that would have passed the build

The exponent that is not there

The obvious implementation ranks with POWER(2, -age/stability) in SQL. SQLite only has pow when built with a specific compile flag — a bet on the shipped native bundle, green on the development machine and broken on someone's deployment. It is also unnecessary: 

-- r is monotone in age/stability, so:
age = @position - n.last_recalled_position   -- a subtraction, not a duration

-- SEEDING: no faintness test at all. Ranking is the engine's job,
-- and a faint entry has to be RANKED to be buried rather than cut.
ORDER BY n.last_recalled_position DESC
LIMIT    @candidates

-- PRUNING: the one place faintness decides anything, because
-- deleting is the explicit intent. @cut from CandidateCutoff.
WHERE    age / stability > @cut AND grade <> @authoritative

-- the app computes the actual r for reporting. no exponent in any database.

A test proves the conversion selects exactly the node set that computing r per row would, across several orders of magnitude of age and stability.

The capability a wrapper erases

This one already shipped once, elsewhere in the library: decorating a generation provider erased its optional capability interfaces, so every video render silently stopped routing while every image render kept working and every inline test stayed green. A composite memory engine is the same hazard. It therefore never guesses — it routes strictly by the owning engine recorded on each reference, and a test submits an expansion through a composite so the regression cannot ship invisibly.

Disclosed, not buried

The constants, and exactly how far they are measured

Nine constants govern forgetting and they interact: edge decay erodes the strength that feeds the connection boost, reinforcement fights the interference the same writes cause, and burst damping changes what a write costs. Measuring them one at a time would measure the wrong thing, so a simulation drives a corpus with a known reuse/noise split through the whole model at once.

DefaultBasis
Hops = 2reasoned three or more reaches most of a connected graph, defeating the purpose
hop attenuation 0.5^hopreasoned halving keeps hop-2 material below hop-1
co-activation cap = 5reasoned bounds edge writes at 10 per turn instead of 45
MaxConnectionBoost = 4reasoned its EXISTENCE is load-bearing: an unbounded boost has no valid candidate cutoff
InitialStability = 20 eventsmodelled how fast one-off noise fades
Reinforce = 0.5modelled how fast repeated context becomes durable
MaxStability = 2000modelled the ceiling that stops “durable” becoming “permanent”
RelativeFloor = 0.02modelled how far below the strongest hit an entry is buried — a backstop, since the item limit does most of the hiding
MinRetrievability = 0.05modelled faded enough to reap — used by prune only, never by recall
EdgeHalfLife = 100modelled how fast a link that stops recurring stops mattering
ConnectionBoost = 0.5modelled how much being well-connected extends a half-life
HeadlineChars = 120 · SimilarityK = 5modelled

Every one is settable by the consuming application. That is not a hedge — a constant nothing has measured against your corpus is the strongest possible case for exposing one.

Closing them was a test, not a judgement call. The simulation asserts outcomes rather than values: at least 90% of the reused set still recallable at the end of the run, at most 10% of the one-off material from the first half, the weakest reused fact outranking the strongest surviving old one-off, and all of it still true when the run is driven twice as long so the numbers are not fitted to one point on the curve.

Two of those assertions are sharper than they look. Decay is measured over the first half deliberately — material written moments ago should still be recallable, because it is recent, and asserting otherwise would be asserting a bug. And burst survival carries a control: a 500-item ingest must not erase prior memory, and the same ingest undamped must erase all of it. Without the control, a regression that silently disabled damping would pass until the corpus happened to grow.

What this does not prove. It measures the dynamics — that reuse outruns interference by the intended margin — and it runs in CI, which a production corpus cannot. It does not establish that real usage has the reuse-to-noise ratio modelled here. So the constants are measured against a stated model, not measured; a starting point, not a tuned value. The XML docs say exactly that rather than dropping the caveat.
Not in scope

Deferred, with the reason attached

  • LLM consolidation — collapsing a dense cluster of weak related nodes into one strong summary and letting the details decay. The most brain-like piece and the most speculative: it needs real recall data to tune, spends tokens every pass, and can destroy information. It earns its own spec once the graph has been running long enough to have something to consolidate.
  • Per-engine databases — engines separate by task and scope, which is what that scoping is for. Physically separate stores is a storage-lifetime problem applying equally to all twelve store interfaces; the provider-side analogue was already solved once, generally, and the storage side deserves the same rather than a memory-specific special case.
  • Per-entry confidence scores — nothing in the library can produce that number honestly, so it would become a knob every caller sets to 1.0.
  • A grade filter on the query — probably right for an agent that wants only hard facts. Deferred until a caller asks, since every public member is permanent.
